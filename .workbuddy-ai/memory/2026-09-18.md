# 2026-09-18

## 修复构建报错：Rollup `Could not resolve "./net/NetConstants" from "src/index.ts"`

**现象**：`npm run auto-p` → `gulp` build 阶段 371ms 即失败，报错信息被 gulp 吞掉（只留三行 rollup 栈），无可用提示。

**根因（三层）**：
1. Rollup 真实报错为 `Could not resolve "./net/NetManager" from "src/index.ts"`，plugin 归属 `rpt2`。
2. 拦截 `rollup-plugin-typescript2` 的 `resolveId` 后发现：**所有相对 import 均返回 `undefined`**，并非某个文件的问题。
3. rpt2 内部 `createFilter(included, excluded, { resolve: parsedConfig.options.rootDir })` 使用默认 include 模式 `*.ts+(|x)` / `**/*.ts+(|x)`。其中 `+(|x)` 为 extglob 语法，**picomatch 2.3.2 起不再匹配任何路径**（2.3.1 下 `**/*.ts+(|x)` 匹配成功，2.3.2 下失败）→ filter 全部返回 false → `resolveId` 返回空；同时 `transform` 中的 `if (!filter(id)) return` 也会跳过编译。

**触发源**：`package-lock.json` 被更新（commit `b95ca81 update lock file`），其中 `picomatch 2.3.1 → 2.3.2`、`@rollup/pluginutils` 被解析为 4.2.1。rollup 3.15.0 / typescript 4.9.5 / rpt2 0.34.1 均未变化。

**修复**：`gulpfile.js` 中给 `typescript()` 显式传入普通 glob，绕开 extglob：
```js
const tsPluginOptions = {
    include: ['**/*.ts', '**/*.tsx'],
    exclude: ['**/*.d.ts'],
};
plugins: [typescript(tsPluginOptions), terser()]
```

**验证**：`npm run build` 22s 成功；`lib/index.js` 31KB（terser 压缩后的合法 ESM，无残留 TS 语法，enum 已编译），`lib/index.d.ts` 及 `dom/ net/ react-hooks/ utils/` 声明文件均正常生成。

**备注**：未执行 `npm run p`（含 `npm version patch` + `npm publish` + `git push`），属外部不可逆操作，待用户确认。
